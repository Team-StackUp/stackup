## 0. 결론

1. **현재 서버(GTX 1660 Ti 6GB)로 Gemini 를 대체하는 것은 불가능하다. 원인은 설정이 아니라 하드웨어다.**
   프롬프트 처리 속도가 어떤 설정·서빙 스택에서도 **초당 약 240토큰**에 묶였다. 병렬 슬롯을 켜도 동시 4명 기준 처리량은 18.4 → 21.4 요청/분(+16%)에 그쳤고, 부하 구간의 39%가 80W 전력 상한에 걸렸다.
2. **로컬 품질은 모델 크기에 따라 갈린다.** 이 서버 GPU 에 올라가는 4B급 이하 모델은 블라인드 품질(Claude 판정) 꼬리질문 최고 3.0점, 코칭 최고 3.0점으로 Gemini Flash-Lite(4.1점, 4.0점)에 못 미친다. 반면 **Gemma 4 26B-A4B 는 3비트로 깎은 상태에서도** 꼬리질문 3.7, 질문 풀 4.2, 코칭 4.3점으로 Gemini 에 근접하거나 같았다.
3. **따라서 "로컬 LLM" 은 GPU 를 바꾸는 결정이다.** 24~32GB GPU(중고 RTX 3090 ~₩1.0~1.35M, RTX 5090 ~₩5.5M)에서 Gemma 4 26B-A4B 를 4비트 이상으로 돌리는 구성이 품질·속도 모두 현실적인 후보다. 다만 현재 사용량(누적 세션 95건)에서는 **비용상 이득이 없고**(자체 서버가 싸지는 지점: 월 약 2,400~5,500 세션), 게이트웨이는 무료다.
4. **당장 할 수 있는 것**: (a) 구매 전 GPU 를 몇 시간 임대해 같은 하네스로 Gemma 4 26B-A4B 를 실측, (b) 공유 Ollama 의 **GPU 끊김(무경고 CPU 폴백) 대책** 적용, (c) 게이트웨이 장애 대비 폴백이 필요하면 현 서버에 Gemma 4 E2B 를 전용 llama.cpp 컨테이너로 두되 **동시 1~2명까지만** 쓰는 제한적 모드로.

## 2. 리서치 요약

### 2.1 서빙·최적화

- **Ollama 최신은 v0.34.1(2026-09-14).** 서버의 0.20.7 은 5개월 전 버전이다. v0.30 부터 내부 엔진이 llama.cpp `llama-server` 로 바뀌었고 `OLLAMA_NUM_PARALLEL` 을 켜면 요청을 한 번의 연산으로 묶어 처리한다. 기본값 1 은 완전 직렬이다.
- **llama.cpp 병렬 슬롯**: `-np N`(슬롯 수), 연속 배칭 기본 켜짐, `-c` 는 전체 문맥을 슬롯 수로 나눈다. KV 캐시 `q8_0` 양자화로 메모리 절반. 동급 이상 GPU(RTX 3060) 공개 벤치마크에서 3.8B 모델 생성 처리량이 1→8 병렬에서 108→276 tok/s 로 늘었다.
- **최소 지원 버전**: Kanana-2 는 2026-02 이후 llama.cpp, Gemma 4 `-qat` 태그는 Ollama 0.30.6 이상, Qwen3.5 는 0.17.4 이상.
- **MoE CPU 오프로드**: `--n-cpu-moe N` 으로 전문가(expert) 가중치만 CPU 에 두고 어텐션은 GPU 에 둔다. 6GB + RAM ~11GB 에서는 파일 크기 12GB 이하(2~3비트)만 현실적이며, 생성 8~18 tok/s·프롬프트 300~800 tok/s 로 추정됐다.
- **JSON 스키마 강제**: llama.cpp `response_format.json_schema`·GBNF 지원. `$ref` 포함 스키마는 조용히 무시되는 알려진 이슈가 있어 서버 측 검증이 여전히 필요하다.

### 2.2 GPU 끊김 원인

- **알려진 NVIDIA Container Toolkit 문제**: runc + systemd cgroup 드라이버 환경에서 `systemctl daemon-reload` 가 일어나면 실행 중인 컨테이너의 GPU 장치 접근이 사라진다. 증상은 `failed to initialize CUDA` 또는 NVML 오류이며 Ollama 는 **오류 없이 CPU 로 폴백**한다. 서버 설정(toolkit 1.19.0, runc)이 해당 조건이다.
- `docker compose up --build` 자체가 daemon-reload 를 부르는지는 확인되지 않았다(미확정). 패키지 설치·자동 업데이트도 흔한 트리거다.
- **대책**(모두 sudo 필요): cgroupfs 드라이버 전환, compose 에 `/dev/nvidia*` 장치 명시, `nvidia-ctk system create-dev-char-symlinks`, CDI 모드. **감지**: `nvidia-smi -L` 헬스체크, Ollama `/api/ps` 의 `size_vram < size` 경보, 컨테이너 재시작으로 복구.

## 4. 결과

### 4.1 GPU 처리 한계 — 설정으로는 안 바뀐다

2.5k 토큰 한국어 프롬프트, Qwen3 4B Q4_K_M, 슬롯 1개.

| 설정 | 프롬프트 처리 (tok/s) | 생성 (tok/s) |
|---|---|---|
| llama.cpp, 플래시 어텐션 on | 246 / 238 | 60 / 59 |
| llama.cpp, 플래시 어텐션 off | 226 / 218 | 23 / 44 |
| llama.cpp, 마이크로배치 1024 | 245 / 246 | 59 / 60 |
| llama.cpp, 마이크로배치 256 | 241 / 235 | 59 / 60 |
| Ollama 0.20.7 (공유) | 239 | 55 |

- **모든 설정에서 프롬프트 처리가 ~240 tok/s** 로 같았다. 운영 꼬리질문 입력 중 캐시되지 않는 고유 부분(답변·대화 이력·검색 문맥, 추정 700~1,500 토큰)만으로 3~6초, 질문 풀(3~5k 토큰)은 12~20초가 프롬프트 읽기에 든다.
- 병렬 처리 시 요청당 프롬프트 처리는 150 tok/s 안팎으로 떨어지고, 생성은 4병렬에서 요청당 8~27 tok/s 로 나뉜다. **총 처리량은 1병렬 19.6 → 4병렬 22.6 tok/s(프롬프트 포함)** 로 거의 늘지 않았다.
- 원격 측정: 부하 구간(40W 이상) 2,324건 중 **907건(39%)이 80W 소프트웨어 전력 상한**에 걸렸다. 최고 75°C, 온도 스로틀은 없었다.

## 6. 권고 및 다음 단계

1. **운영은 A 유지.** 이번 실험으로 "설정만 바꾸면 현 서버로 된다"는 가능성은 닫혔다.
2. **로컬 전환을 계속 추진한다면 구매 전에 임대로 검증한다.** RunPod 등에서 RTX 3090/4090/5090 을 몇 시간(시간당 $0.22~0.99) 빌려, 이 저장소의 `run_eval.py`·`load_test.py`·`judge.py` 로 **Gemma 4 26B-A4B 를 Q4/FP8 로** 품질·동시성을 실측한다. 기준: 꼬리질문 Claude 판정 3.9 이상, 동시 4명 꼬리질문 3초 이내, 피드백 fan-out 중 꼬리질문 3초 이내.
3. **GPU 끊김 대책을 공유 서버 관리자와 적용한다.** 다른 프로젝트(devlog·devtalk·mcp)도 영향받는다. 최소한 `nvidia-smi -L` 헬스체크와 CPU 폴백 감지 경보.
4. **게이트웨이 장애 폴백이 필요하다면** C 안: 공유 Ollama 가 아닌 전용 llama.cpp 컨테이너에 Gemma 4 E2B, `-np 2`, `num_ctx 8192`, `keep_alive` 상시, 헬스체크 포함. 폴백 중에는 피드백 코칭을 순차·지연 처리하도록 제한.
5. **공유 Ollama 업그레이드(0.20.7 → 0.34.x)** 는 다른 프로젝트와 조율이 필요하다. 이번 실험은 별도 컨테이너로 우회했다.
6. 게이트웨이 대안 비교를 끝내려면 **외부 API 키**(OpenRouter 등)로 Qwen3.8-Flash·gpt-oss-120b 를 같은 하네스로 측정한다.

## 7. 한계

- **3비트·2비트 품질은 하한선이다.** Gemma 4 26B-A4B·Qwen3.6-35B-A3B 는 원래 4비트 이상으로 쓰는 모델이며, 24GB GPU 에서의 품질은 이보다 높을 것으로 예상하지만 실측하지 않았다.
- 판정은 LLM 판정이며 케이스는 합성 22개다. 상위권 간 0.1~0.3점 차는 오차 범위로 본다. Gemini 판정자의 Google 계열 편향이 이번에도 관찰됐다.
- 중형 MoE 는 반복 1회, 소형은 2회 측정이다.
- 하드웨어 가격·타사 벤치마크 수치는 리서치 인용값으로 엔진·양자화·프롬프트 길이가 우리 조건과 다르다. 한국 중고가·국내 클라우드 가격 일부는 미확정이다.
- GPU 끊김 원인은 리서치 가설과 시각 상관으로만 뒷받침되며 서버 권한 없이 재현하지 못했다.
- Kanana-2-30B 는 4비트 파일만 공개되어 있어 이 서버 메모리에 맞추려 2비트로 재양자화했고, 그 결과가 깨져 품질을 측정하지 못했다.
